Topic 1 · print()

print() shows something on the screen

Put what you want to show inside the brackets. Text goes in quotes, numbers do not. Run it and read the output below the cell.

Pro tip. Every run starts at the top and goes down one line at a time. Change the text and run again: you cannot break anything.
Topic 1 · print()

Many values, one line, and how to join them

Give print() several values separated by commas. It puts a space between them and a new line at the end. sep changes the gap, end changes the ending.

Watch out. sep and end must be written with their names. They always come after the values.
Topic 1 · Text

Quotes tell Python: this is text

Single or double quotes make no difference. Pick the one that avoids extra work when the text itself contains a quote.

Escapes

\n new line  ·  \t tab  ·  \\ one backslash  ·  \' a quote. A backslash inside text says: the next character is special.

Topic 1 · Comments

A comment is a note for humans

Anything after # on a line is ignored by Python. Use comments to say why, not to repeat what the code already says.

Pro tip. Putting # in front of a line to switch it off is called commenting it out. It is the fastest way to test without deleting.
Topic 1 · Statements

One statement per line, and how to split a long one

Python reads one statement per line. There is no ; to end it. When a line gets long, break it inside brackets, or end the line with a backslash.

Two ways to continue a line
  • Inside brackets ( ) [ ] { }: just press Enter. This is the style most people prefer.
  • A backslash \ as the very last character on the line.

Variables and lists come in the next topics. Today only notice that one statement can span several lines.

Topic 1 · Indentation

In Python the spaces at the start of a line matter

Other languages use braces or keywords to group lines. Python uses indentation. A line that ends with : opens a block, and the indented lines under it belong to it.

Read it like this
  • The first two lines with 4 spaces run only if the test is true.
  • print('Done') is back at the left edge, so it always runs.
  • Use 4 spaces for each level, the standard.

Common mistake

Text without quotes is a name, not text

Without quotes Python looks for a variable called Hello. It does not exist, so you get a NameError.

Broken
Fixed
Watch out. NameError: name 'Hello' is not defined means: you used a word Python has not been told about. Add quotes if you meant text.
Common mistake

Every opening quote needs a closing quote

Open a quote and forget to close it and Python reads on, looking for the end of the text. It never finds it.

Broken
Fixed
Watch out. SyntaxError means Python could not even read the line. The message says the text never ended. Look at the quotes first.
Common mistake

Every opening bracket needs a closing bracket

Brackets work in pairs. The error often appears on the next line, because Python was still waiting for the closing bracket.

Broken
Fixed
Watch out. '(' was never closed points at the bracket you opened. Count your brackets: opens must equal closes.
Common mistake

The Python 2 habit

In old Python 2, print 'Hello' worked. In Python 3, print is a function, so it needs brackets. Old tutorials still show the old way.

Broken
Fixed
Watch out. Python 3 even suggests the fix: Missing parentheses in call to 'print'. Did you mean print(...)? When you copy old code, add the brackets.
Common mistake

A block needs an indented line under it

A line ending with : promises a block. If the next line is not indented, or an unexpected line is indented, Python refuses.

Broken
Fixed
Watch out. expected an indented block means: add 4 spaces. unexpected indent means: remove spaces that should not be there.
Common mistake

Never mix tabs and spaces

A tab and four spaces can look the same on screen but are different characters. Mixing them in one block gives a TabError.

Broken
Fixed
Watch out. Set your editor to insert 4 spaces when you press Tab. VS Code does this for Python by default.

Topic 1 · Style

Python has a style guide and a philosophy

PEP 8 is the official style guide: 4 spaces per indent, lines up to 79 characters, snake_case names, spaces around operators. import this prints the Zen of Python.

Three lines worth remembering
  • Readability counts. You read code far more than you write it.
  • Simple is better than complex.
  • Errors should never pass silently. Read the message, it is trying to help.

Interview Studio

Five questions asked on day one

What changed about print between Python 2 and 3?
In Python 2 it was a statement: print 'x'. In Python 3 it is a function and needs brackets: print('x'). The old form is a SyntaxError in Python 3.
What do sep and end do in print()?
sep is what goes between values (default one space). end is what goes after the last value (default a new line).
Is there a difference between 'single' and "double" quotes?
No. Both make the same text. Choose the one that avoids a backslash, for example "It's", and be consistent.
How does Python know where a block ends?
By indentation. Lines indented the same amount under a : line form the block. The standard is 4 spaces. Mixing tabs and spaces gives a TabError.
How do you learn what an unfamiliar function does?
help(function) shows its manual, and dir(value) lists what a value can do. The official docs go deeper.

Key Takeaways

Five rules to remember

1 · print() shows output

Text in quotes, numbers without. sep and end shape the line.

2 · Quotes make text

Single or double, both fine. Close every quote and every bracket.

3 · # is a comment

Write why, not what. Comment out a line to test without deleting.

4 · Indentation is syntax

4 spaces per level. Never mix tabs and spaces.

5 · Read the last error line

SyntaxError, NameError, IndentationError each say what is wrong.

6 · Python helps you

help(), dir() and import this are always there.
